## Objective

Shape an interface flow quickly without getting stuck in visual design details.

## When to use this

Use breadboarding when you need to answer:

- where the new capability fits
- how users get to it
- what key interactions are required
- what the main path and edge paths are

## Inputs

- Problem statement
- Appetite
- Existing user flow or baseline screen

## Method

1. List places (screens, dialogs, menus).
2. List affordances at each place (buttons, fields, links, text prompts).
3. Draw connection lines showing movement between places.
4. Walk the primary user path end-to-end.
5. Mark unclear transitions and data assumptions.
6. Repeat until the path is understandable and bounded.

## Breadboard checklist

- Every affordance leads somewhere explicit.
- Preconditions are visible (data needed, permissions, states).
- Out-of-scope paths are intentionally omitted.
- The flow fits the appetite.

## Anti-patterns

- pixel-level mockups too early
- unresolved flow branches hidden in notes
- solving all edge cases before the main path works

## Output

A one-page flow artifact that can be included directly in a pitch.
