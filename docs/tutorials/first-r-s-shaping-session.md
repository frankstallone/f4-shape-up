# Tutorial: Run Your First R/S Shaping Session

## Goal

Shape one real problem using the R/S method, then exit with a selected shape ready for slicing.

## Prerequisites

- One concrete product problem
- One facilitator (shaper)
- One collaborator who can challenge assumptions
- 60-90 minutes

## Step 1: Start from requirements (R)

Capture requirements as numbered items.

- Use `R0` for the core goal.
- Add `R1`, `R2`, `R3` for must-haves and constraints.
- Keep requirements solution-agnostic.

## Step 2: Sketch at least two shape options (S)

Create shape options with letters.

- `A`, `B`, `C` are alternatives.
- Give each shape a short descriptive title.
- Write parts as mechanisms, not intentions.

## Step 3: Run a fit check matrix

Compare all requirements against all shape options.

```markdown
| Req | Requirement | Status | A | B |
|-----|-------------|--------|---|---|
| R0 | Core outcome text | Core goal | ✅ | ✅ |
| R1 | Constraint text | Must-have | ❌ | ✅ |
```

Rules:

- Use binary scoring only: `✅` or `❌`.
- Keep full requirement text in every row.
- Put failure explanations below the table.

## Step 4: Select one shape and tighten it

Pick the shape with the best fit and remove major unknowns.

- If a requirement is still unclear, add or refine an `R` item.
- If a part is unknown, flag it and decide whether to spike it.
- Re-run fit check after updates.

## Step 5: Breadboard the selected shape

Map places, affordances, and connections for the selected shape.

- Validate the primary user path.
- Expose key unknown transitions.
- Confirm fit to appetite before moving on.

## Step 6: Exit with slice-ready output

You are ready to slice when:

- one shape is selected
- fit check for the selected shape is all `✅`
- breadboard is clear enough to plan vertical slices
